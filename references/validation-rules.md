# 验证规则

## 错误

以下问题会使脚本以非零状态退出：

- JSON 无法解析或必要文件缺失；
- `requirements.json`、`page-map.json`、`page-brief-gate.json` 或 `page-specs/*.json` 不符合项目 JSON Schema；
- 来源文档缺少 SHA-256、文件内容已变化、来源行号越界，或短引文无法在声明行号内精确核验；
- 页面地图没有记录用户确认、确认依据和有效日期，或其引用的 `requirements.json` 已在确认后变化；
- 已存在的页面定义确认关卡未通过，或关卡页面与本轮 `built / planned` 页面不一致；
- 本轮页面没有且只有一份独立 MD、两个页面复用同一路径、技能生成文档的 `page_id` 不一致，或页面定义缺少定位、结构、内容数据、交互、状态和原型制作说明；
- 页面定义仍有未关闭的结构问题，或 `page-map.json` 已在逐页确认后变化；
- 页面定义没有记录用户逐页确认，或确认后 MD 内容变化导致 SHA-256 不一致；
- 页面定义确认开关被关闭，但没有记录用户明确授权、时间、原因和证据；
- requirement、page 或 annotation ID 重复；
- 需求没有来源，或引用不存在的来源文档；
- 分类值、确认状态或实现状态非法；
- 已确认页面引用不存在的需求；
- `built` 页面缺少 page spec 或 HTML；
- page spec 与 page map 的页面 ID 不一致；
- 目录或跳转引用不存在的页面；
- 页面缺少正常态，或未声明空、错误、无权限状态的适用性；
- 页面说明缺少类型、名称、说明、需求引用或坐标绑定；
- 开发交付说明 v2 的标注没有声明覆盖对象，或 `content` 没有按适用维度分段；
- 开发交付说明 v2 未覆盖页面全部区块、字段、操作和适用状态，或引用了不存在的覆盖对象；
- 模块完整标注 v2.1 缺少 `annotationPolicy`，或策略不是 `module-complete`；
- v2.1 未声明 `coverageScope`；增量页面缺少 section 变更状态或变更原因；
- v2.1 页面存在没有模块主标注的 section、重复 moduleId，或模块主标注一次覆盖多个 section；
- `change-impact` 页面为 `unchanged` 模块生成了标注，或漏掉 `new / changed / impacted` 模块；
- v2.1 模块主标注缺少 `definition`，结构化说明不足三个适用维度，或明细没有 dimension；
- v2.1 模块主标注的 anchorId 没有绑定该模块自身或明确声明的 DOM 锚点；
- v2 选择型字段既没有固定选项，也没有动态数据来源；
- v2 操作没有可执行的 `logic` 说明；
- v2 页面缺少角色、入口、出口、前置条件，或其中存在空条目；
- v2 页面没有声明业务状态变化数组，或状态变化缺少来源需求；
- v2 页面缺少 GIVEN / WHEN / THEN 验收标准；
- v2 待确认事项仍是纯文本，缺少影响、确认状态或当前假设；
- 案例的 `index.html`、`viewer.css` 或 `viewer.js` 与标准查看器模板不一致；
- 已生成页面未出现在确认后的目录树中，或在目录中重复出现；
- 多页面项目没有文件夹层级，或目录深度超过三层；
- `unresolved` 需求被标记为 `confirmed`；
- 关键需求既没有页面覆盖，也没有明确未覆盖原因。

## 警告

以下问题允许样例交付，但需要在报告中处理：

- 页面地图尚未通过产品确认关卡；
- 旧项目尚未建立 `page-brief-gate.json`；兼容校验仅提示警告，新任务在开始原型实现前仍必须通过严格关卡检查；
- 标注只有回退坐标，没有稳定 DOM 锚点；
- 页面规格存在待确认项；
- `prototype.json` 中的页面或标记未能与中间模型完整对应；
- 页面规格仍使用旧版重点备注，尚未升级为开发交付说明 v2；
- 标注标题包含“必须、不得、不可、需要”等规则措辞，可能把逻辑结论误写成了对象标题；
- 已构建页面的可见文本、交互反馈或无障碍名称包含典型研发/原型措辞，可能没有从目标用户视角改写；
- v2 页面没有关联需求、接口或业务规则入口；
- 已规划或延期页面没有目标版本。

## 报告

报告固定写入 `intermediate/validation-report.md`，包含运行时间、输入路径、错误、警告和统计。报告只证明结构与追溯关系通过，不证明视觉质量、业务正确性或生产可用性。

修改技能脚本或 Schema 后必须运行 `node tests/run-tests.js`。测试至少覆盖来源变更、页面地图未确认、MD 路径重复、确认后内容变更和绕过开关边界。

开始业务 HTML、CSS 或 JS 实现前，必须单独运行严格关卡检查：

```bash
node scripts/check_page_brief_gate.js \
  --project "my-project/prototype"
```

严格检查中缺少关卡文件也属于错误；`validate_artifacts.js` 对历史案例缺少关卡仅保留兼容警告。
