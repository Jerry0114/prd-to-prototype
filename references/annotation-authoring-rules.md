# 模块标注规则 v2.2：准确、简洁、完整

本规则用于生成能独立支持产品评审和开发交接的页面标注。目标不是增加点位数量，而是准确说明本轮需要开发或修改的模块；既有页面中的未改内容只作为上下文，不重复标注。

## 1. 基本原则

- 先完成模块清单和变更判定，再写标注。`page-spec.sections[]` 可以保留页面上下文模块，但必须区分本轮变更范围。
- 新建页面使用全页覆盖；既有页面增量改造使用变更影响覆盖，只为新增、修改或确实受影响的模块生成标注。
- 纳入本轮标注范围的 `section` 必须且只能对应一条主模块标注，使用 `scope: "module"` 和 `moduleId: <section-id>` 建立关系。
- 一条主模块标注的 `covers` 只能包含一个 `section:*`；相关字段、操作和状态可以一并覆盖。
- 不允许用“核心区域”“页面重点”等宽泛标注一次吞并头部、推荐位、广告位和内容列表。
- 页面级加载、空、错误、权限或失效逻辑可使用额外的 `scope: "page"` 标注，不占用模块主标注。
- 标注正文只使用 `title` 和 `content` 两个字段。标题只写模块对象名称；结论、规则和动作全部写入内容。
- 需要区分多类规则时，在同一 `content` 中使用“模块定义、展示内容、数据规则、交互逻辑、异常与状态、布局说明、合规说明、关联文档”等段落标题，不再创建 `type / description / details / relatedDocs`。
- 固定顺序、排序字段、过滤条件、数量、审核、接口参数和原型范围等研发规则应保留在标注内容中，不要为了“让规则可见”而把它们重复写进业务界面文案。

## 2. 覆盖范围判定

在 `handoff.annotationPolicy.coverageScope` 中声明覆盖方式：

- `full-page`：全新页面或本轮整体重构页面。所有一级业务模块都需要独立标注。
- `change-impact`：在既有页面上新增或调整功能。只标注本轮新增、修改或被改动影响的模块。

`change-impact` 页面必须为每个 `sections[]` 模块声明 `changeStatus`：

| changeStatus | 含义 | 是否生成模块标注 |
| --- | --- | --- |
| `new` | 本轮新增模块 | 是 |
| `changed` | 既有模块的内容、数据、交互、状态或结构被修改 | 是 |
| `impacted` | 模块自身规则因其他改动而必须联动调整 | 是 |
| `unchanged` | 只作为原页面上下文展示，本轮没有修改 | 否 |

判定边界：

- 旧模块只是因为插入新模块而整体下移，不算 `impacted`。
- 旧模块只是出现在还原截图或完整页面上下文中，不算 `changed`。
- 旧模块的接口、字段、交互、状态、组件结构或展示规则发生变化，才算 `changed` 或 `impacted`。
- `unchanged` 模块必须写 `changeReason` 说明其为既有内容，且不得生成 marker 或模块标注。
- 页面级状态标注仅在本轮确实修改全页状态时生成；若异常规则只属于新增模块，应写进该模块标注。

## 3. 模块如何划分

满足任一条件时，应独立成为 `section`：

- 有独立业务目的或用户任务；
- 有独立数据来源、筛选、排序、数量或更新规则；
- 有独立点击、滑动、输入、关闭、分页或跳转；
- 有独立加载、空、失败、权限或降级表现；
- 在视觉上是可识别的头部、导航、推荐位、广告、卡片组、列表、正文、提示或底部操作区。

纯装饰背景、分割线、图标和无独立语义的容器不单独作为模块。重复列表项通常由一个列表模块统一说明，但要在内容维度中写清单项结构。

## 4. 单个模块的内容分段

新生成规格使用 `handoff.version: "2.2"`。保留 `title + content` 契约；标题定位对象，正文直接解释可实现的规则。按模块类型选择适用维度，不再强制模块定义或至少三段。标题已说明用途时，不重复“呈现某某信息”。

页面 `annotationPolicy.requiredDimensions` 声明全页共同必需维度（可以为空数组），`minimumApplicableDimensions` 最小为 1；每条模块标注的 `requiredDimensions` 补充该对象必需维度。两者合并校验，标题和正文必须同时存在，空段、占位段和重复维度不算覆盖；关联文档不计入最低说明维度，不能只放一个链接代替说明。v2.1 保留定义与至少三维度的旧契约，不静默改变旧项目版本。

| 段落标题 | 要回答的问题 |
| --- | --- |
| 模块定义 | 模块是什么、解决什么问题、在页面中的边界是什么 |
| 展示内容 | 展示哪些字段、文案、图片、标签、按钮或列表项 |
| 数据规则 | 数据来源、过滤、排序、数量、默认值、刷新和时效规则 |
| 交互逻辑 | 点击、滑动、轮播、输入、跳转、来源参数和返回逻辑 |
| 异常与状态 | 加载、空、失败、无权限、失效、降级和恢复方式 |
| 布局说明 | 固定尺寸、顺序、响应式、吸顶、截断或滚动规则 |
| 合规说明 | 风险提示、披露、审核、脱敏或不可关闭规则 |
| 关联文档 | PRD、接口文档或业务规则的名称、路径和可选章节 |

段落标题单独占一行，正文紧随其后；段与段之间保留一个空行。不要把段落序列化为 JSON 字符串，也不要使用额外嵌套数组。

### 事实、归属与去重

- 先提取对象、触发条件、规则、结果和来源，再写正文；PRD 未说明的接口、权限、数量和排序不得补造。
- v2.2 的 `fields[]`、`actions[]` 必须用 `moduleId` 指向所属 section，局部状态同样声明 `moduleId`；不声明模块的状态属于全页，由右侧状态说明交付，不强塞进某个模块凑 covers。
- 模块标注只能覆盖自身字段、动作和局部状态；跨模块影响只描述交接关系，不复制整套规则。筛选区说明条件如何影响结果，列表说明结果与下钻，操作区说明完成/返回。
- `change-impact` 中，字段/操作/局部状态默认继承所属模块的变更范围；有例外时用自身 `changeStatus + changeReason` 明示。变更子项的父模块不能仍是 `unchanged`。全页状态变化在状态模型中说明；需要独立详细解释时才增加 page 标注。
- 项目级演示数据和公共文档放概要/交付；通用状态规则放状态页签。模块只保留自身触发条件、特殊表现和恢复路径，避免每条重复“不涉及权限/过期”等声明。
- 每条只引用实际相关的需求。可用 `ruleSources[]` 记录 `dimension / classification / requirementRefs / note`；明确规则用 `explicit`，实际代码行为用 `implemented` 并说明实现依据，推断/建议/未决分别用 `inferred / proposed / unresolved`。未决业务进入 `openQuestions`，不能伪装成已确认事实。
- 不硬限字数；重复度只触发复查提醒。简洁不能删除默认值、禁用、失败恢复、布局或合规约束。程序证明结构与来源存在性，语义仍须逐模块复核。

## 5. 按模块类型选择说明

### 页面头部和导航

说明标题/操作构成、返回或跳转规则。只有模块边界不清时补定义；吸顶、滚动变化、状态栏和无来源兜底按业务适用性补充。

### 推荐位和轮播

至少说明：推荐位定位、卡片字段、取数与排序、数量上下限、自动/手动切换、计时重置、点击参数、少数据和失败表现。

### 广告位

至少说明：广告定义、素材尺寸、数据来源与有效期、点击目标、关闭逻辑、无广告/素材失败/链接无效时是否收起。广告规则不能混写到推荐位标注中。

### 栏目矩阵和快捷导航

至少说明：导航目的、固定或动态项、顺序、单元内容、点击热区、目标页面和参数、栏目不可用时的处理。

### 内容卡片和列表

说明单项字段、数据范围、点击去向；过滤、排序、数量、分页/加载更多及局部空/失败处理按实际需求补齐，不为“不存在分页”创造分页规则。

### 筛选器与操作区

筛选器写默认选项、条件组合、触发时机、清空与条件保留。操作写可操作条件、结果、禁用、重复提交和失败恢复；不要把详情操作写进列表筛选区。简单静态模块可只有一段有效说明，复杂交互和高风险模块应声明相应必需维度。

### 详情头部、摘要和正文

分别作为独立模块。详情头部说明身份和操作；摘要说明来源和字号关系；正文说明内容结构、富文本规则、图片和字号；不能合并成一条“文章内容”标注。

### 风险提示和合规区域

至少说明：展示位置、文案来源、是否固定必显、能否关闭、内容失效或不可访问时的处理。

### 页面状态

使用 `scope: "page"` 单独说明全页加载、空、错误、无权限和失效的触发、保留内容、操作和恢复路径。模块自身的局部状态仍写在对应模块标注中。

## 6. 数据结构示例

```json
{
  "id": "ANN-HOME-RECOMMEND",
  "scope": "module",
  "moduleId": "home-recommend",
  "title": "推荐文章",
  "content": "模块定义\n位于页面头部之后，用于优先曝光运营推荐内容。\n\n展示内容\n每张卡片展示栏目、标题、摘要和图片。\n\n数据规则\n展示2至4篇有效推荐文章，各栏目最多一篇。\n\n交互逻辑\n每5秒循环；手动横滑后重新计时；点击携带content_id进入文章详情。\n\n异常与状态\n少于2篇时停止自动轮播；请求失败由页面错误态承接。",
  "covers": [
    "section:home-recommend",
    "field:home-recommend-article",
    "action:home-open-article"
  ]
}
```

## 7. 完成前检查

1. 页面上每个一级业务模块是否都出现在 `sections[]`，并正确选择 `full-page` 或 `change-impact`。
2. 增量页面是否为每个 section 声明了真实 `changeStatus`，未改模块是否没有 marker。
3. 本轮范围内的每个 `section` 是否恰好有一条 `scope: module` 的主标注。
4. 主标注的锚点是否落在该模块自身，而不是页面其他位置。
5. 每条是否有实际正文、是否覆盖声明的必需维度，且没有空段、占位段或为了凑段落复制通用说明。
6. 推荐、广告、导航、列表、正文和风险提示是否分别说明，没有互相代写。
7. 本轮新增或修改的字段、操作和适用状态是否被 `covers` 完整覆盖。
8. 说明是否能回答“是什么、展示什么、数据怎么来、用户怎么操作、异常怎么办”中的适用问题。
9. 未确认的数据口径或接口规则是否明确标注为待确认，没有伪造成产品事实。
10. 研发规则是否完整留在标注中，同时没有泄漏到目标用户可见的业务文案、状态提示或交互反馈中。

## 内容重跑与数据一致性

默认读取 `intermediate/annotation-source.json` 的 `pages[].modules[]`，也可用 `--source <相对或绝对JSON路径>` 指定；兼容旧 `assets/prototype-data.js` 的 `window.PrototypeData.pages`。这是有依据的规则数据输入，不是自动从任意 JS/PRD 提取事实的引擎；不得把查看器的 `window.PROTOTYPE_DATA` 镜像当作来源。

模块字段 `contentRule/content/data/interaction/state/layout/compliance/docs` 对应八种说明维度。未提供字段保留旧段；空值/占位值拒绝覆盖。需要删除时用 `removeDimensions: ["layout"]` 显式声明，不能同时更新和删除同一维度。未知自定义文本保留；旧结构字段先迁移。`requiredDimensions/requirementRefs/ruleSources` 仅在来源明确提供时更新。

先 `--dry-run`，确认差异再写入；整批存在缺失页面、重复 ID、未匹配模块或无效正文时不写任何规格。成功时同步 page-spec、prototype.json 系统标注及实际存在的查看器 JS 镜像；业务 JS、锚点 ID 和人工差异层保持不变。查看器以成功读取的 page-spec 标注为系统基线，读取失败时才使用镜像。重跑不重新做产品确认，也不自动提升来源可信度。

## 8. 锚点运行规则

- `bindingStatus: "bound"` 时，`anchorId` 必须对应业务页面中稳定且唯一的 DOM `id`；查看器在 iframe 加载完成后按该元素的文档坐标定位标记。
- `anchor.offset.x/y` 是相对锚点左上角的业务页面像素偏移；查看器负责按业务视口与缩略画布比例换算，不得把 offset 当作查看器窗口坐标。
- `anchor.fallback.x/y` 只用于跨域、锚点缺失或页面尚不可访问时的回退，坐标空间固定为 `reference-viewport-percent`；成功绑定后不得继续显示回退位置。
- 页面异步渲染、模块尺寸变化、iframe 滚动或查看器尺寸变化后，标记必须重新计算或同步位移，不能停留在首次加载时的位置。
- 已绑定但当前隐藏的抽屉、弹窗或状态面板不得显示在回退坐标。打开该模块的可见控件应声明 `data-prototype-trigger-for="<module-id>"`；查看器在目标隐藏时将标记定位到该入口，目标打开后再自动迁移到真实内容。
- 预览入口必须是实际触发该模块的按钮、链接或可操作行；不得为了让数字出现在首屏而把入口标记复制到页面标题、表格首列或其他无关容器。
- 一个可见入口同时打开多个连续模块时，从属模块在 `anchor.previewTriggerId` 中复用主模块的触发标识，并用 `anchor.previewOffset` 错开数字；不得为此恢复无关的百分比点位。
- 隐藏目标既没有可见触发入口，也没有可解释的预览锚点时，标记才暂时隐藏；这种情况应在交付前补齐入口绑定。
- 验收时至少抽查页面首屏模块、首屏下方模块和可滚动模块各一个，确认数字标记落在其 `anchorId` 对应模块内，而不是仅验证 JSON 中存在锚点字段。
